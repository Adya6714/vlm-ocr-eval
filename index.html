Research · scroll this like a talk

What does OCR confidence actually measure?

We built a small from-scratch OCR instrument (~19.6M parameters) to ask one narrow question: when the decoder says it is ~90% sure, is that because the image supports the text — or because the output just looks like language?

Live walkthrough Scroll down for the story · 0.90 → pos 0 → full profile → blank/noise · then how we built it

Two questions drive everything. A: can we tell when Indic OCR is hard? B: does confidence track visual evidence, or only how peaked the softmax is?

This Research tab answers B inside the instrument — with figures, flowcharts, and a few tap-to-play demos. The Production tab asks what transfers to a real Indic OCR product (without claiming our toy model competes on accuracy).

Why this research exists

Indic OCR is hard — and confidence routing only works if the meter is honest

Production systems expose confidence for triage: send easy pages straight through, escalate hard ones. That only works if confidence tracks difficulty. Indic scripts add layers of measurement pain before you even get to the model.

Unicode code points are not user-perceived characters. Hindi क्ष can be one grapheme cluster built from multiple code points. Character Error Rate (CER) on raw Unicode can punish correct output. We normalize and cluster graphemes so metrics mean something — but the deeper issue is semantic: correctness, confidence, and visual grounding are three different quantities.

A model can be wrong while sounding fluent. A model can be confident while the true first symbol sits at rank ~70 in a 367-way softmax. A model can read aggregate accuracy on Hindi while Kashmiri collapses — and still report page confidence near 1.0.

That separation is the whole research question.

Indic OCR adds script-specific failure modes: conjuncts, matras, reordering marks, font shaping differences. A Latin OCR mental model ("letters left-to-right in boxes") misleads you when discussing Devanagari or Bengali. That is why we shape with HarfBuzz and count grapheme clusters — and why we are cautious comparing headline CER across scripts without reading the normalization spec.

Question A (production) and Question B (mechanism) intersect when someone proposes: "route low-confidence pages to a human." That policy assumes confidence encodes difficulty with visual grounding. Stage 5–6 test a slice of Question A on Sarvam; the instrument probes Question B in depth.

Question A

Can we tell when Indic OCR is hard — across scripts, exposure regimes, and production APIs?

Question B

Does decoder confidence track whether the image supports the text, or only whether the generated string looks like language?

Why not just use Sarvam?

An API gives outputs. It cannot blank the page, zero the encoder, teacher-force p(GT) at position 0, or ablate cross-attention. You need an owned instrument for counterfactuals.

Confidence routing — hope vs what we test

Blank page — does conf drop? Does rank track Sarvam difficulty?

If confidence is only "how peaked is the softmax," routing becomes a lottery dressed up as a meter. That is the failure mode we instrument.

Stage 0 · how we score errors

Tier 0 / 1 / 2 taxonomy before any neural training

Before training our own model, we need a vocabulary for failure. Stage 0 labels Tesseract and baseline outputs so later probes know what "hard" meant on real pages.

Tier 0 is exact match after normalization. Tier 1 captures provisional near-misses worth human review. Tier 2 is everything else. Among Tesseract outputs that are not Tier-0 exact, roughly 20.4% land in Tier 1 — a slice big enough to matter for routing stories but not so big that the label is meaningless.

This stage does not prove anything about confidence. It sets up Stage 1–2 so "error type" and "exposure regime" can be crossed later. Baseline engines (Surya, PaddleOCR) fill gaps for Santhali and Kashmiri where manifests exist.

Why tiers before training?

If you train first and discover your eval set is 90% "trivial exact match," you will think confidence works because easy pages dominate. Tiers force you to look at the provisional slice — the pages a human might still need to check — before any neural net enters the picture.

Tier 1 at ~20.4% of non-exact Tesseract outputs is not a headline result. It is a scope marker: enough ambiguous cases exist that routing could matter, but not so many that the pipeline is pure noise.

Why HarfBuzz? OpenType shaping is how real Indic text renders in browsers and PDFs. Skipping shaping would mean the instrument trains on toy ligatures that never appear in production — a subtle but fatal eval bug.

Bigram synthesis during training means consecutive graphemes on a line follow resampled bigram statistics from the training corpus. Stage 2 · the instrument

Encoder → bridge → decoder on ~367 grapheme tokens

Roughly 19.6 million parameters, vocabulary ~367 clustered graphemes, 2,538 training lines, 5,000 optimizer steps, three random seeds. Small on purpose — we want a legible failure mode, not SOTA accuracy.

Think of three layers: pixels → visual memory → next grapheme. The vision encoder sees the line crop. The bridge holds that memory for cross-attention. The decoder starts at <BOS> and emits one grapheme at a time. “Confidence” is just the tallest bar in that ~367-way softmax — which is why it can look sure while the true symbol sits at rank ~70.

Step 1 · what “0.90” means

Confidence is the peak of ~367 probabilities — not “probability of correct”

At every decoding step the model scores every vocabulary item (~367 grapheme tokens). Softmax turns those scores into probabilities. The number people call “confidence” is simply the largest one.

Ct = maxv P(v | image, previous tokens)

If that max is 0.90, we say “90% confident in its selected token.” That is not the same as “90% chance the OCR is right.”

Token A is not one fixed grapheme. It is whatever wins on that image at that step — maybe क on one line, स on another. The shock is not “the model likes क.” The shock is: whatever wins is almost never the correct first grapheme.

Position-0 predictive entropy ≈ 0.333 nats (sharp, not soft). Median rank of the true grapheme ≈ 70.5 / 367; 35% of sequences put truth below rank 100. Sharpness on the wrong event is worse than a flat “I don’t know” for routing — you skip review precisely when the model is confidently off.

Step 2 · why position 0

No previous text — so the image has to do the work

Later tokens can lean on language: after भा, next is probably र. At position 0 there is only <BOS>. If vision is working, the correct first grapheme should be easy. We check that with teacher-forced p(GT) across 180 image×seed runs.

What this does — and does not — prove

Removing or destroying visual content does not collapse the confidence peak (Probe 3: text 0.9940, blank 0.9899, noise 0.9904). Teacher-forced log p(GT) for real / blank / noise / scrambled also sits in a 0.053-nat band. That supports: these scalars are not measuring visual grounding here.

It does not prove the model learned vision and then ignored it. It may never have learned a useful visual representation. We keep that alternative alive in the paper — which is why a positive-control reader is Priority 1.

Encoder ablation (zero visual memory)

Zeroing cross-attention memory: confidence 0.986 → 0.989 (barely moves). Distribution shape changes: KL ≈ 1.075; ~8% of steps flip argmax.

Say this: vision can change which token wins sometimes; the max-softmax scalar is largely insensitive. Don’t say: “the model doesn’t use vision.”

Undertrained? Unseen scripts?

Held-out CER ~0.985 vs blank ~0.949 — the model is not reading held-out lines in any useful sense, yet confidence stays ~0.99. Unseen-script control: 0 target-script characters generated on 360 evaluations. Probe 3b: loss falls (3.21 → 0.18); real-vs-blank confidence gap stays ~0.

We do not claim the architecture cannot read. We claim this training regime did not produce reading with a useful confidence meter.

Step 5 · 60-second answer

If they ask about position 0 — say this

Open in a call

Position 0 removes the language-prefix confound. Across 180 evaluations the correct first grapheme was never the argmax, yet max probability was around 0.90 and ground-truth probability around 2×10⁻¹¹.

We didn’t stop there. Position 1 is still poor; from positions 2–39 the model recovers to a regime very close to a text-only 4–5-gram, with 91–94% argmax agreement. So the decoder can generate predictable text from linguistic regularities even when the image isn’t providing useful grounding.

Blank and noise don’t collapse confidence — and scramble doesn’t collapse teacher-forced log p(GT) either. I wouldn’t claim we proved “learned vision, then ignored it.” The model may simply be undertrained. That’s why a positive-control reader is the next experiment.

This connects to Production: if instrument confidence does not route well offline (Stage 6), there is no reason to assume max-softmax from a different system will either — without explicit grounding metrics.

Findings summary

What we established — in plain language

Five bullets you can defend with committed jsonl files and docs/paper_defensibility_stats.md.

  1. Dissociation: max-softmax ≈ 0.90 while p(GT) ≈ 10⁻¹¹ at position 0 — on held-out synthetic lines, 0/180 argmax hits.

60-second answer · position 0

Position 0 removes the language-prefix confound. Across 180 evaluations the correct first grapheme was never the argmax, yet max probability was around 0.90 and ground-truth probability around 2×10⁻¹¹.

We did not stop there. Position 1 is still poor; from positions 2–39 the model recovers toward a text-only 4–5-gram, with 91–94% argmax agreement. The decoder generates linguistically predictable text even when the image is not providing useful grounding.

Blank images do not collapse confidence — but I would not claim we proved "learned vision, then ignored it." The model may simply be undertrained. That is why a positive-control reader is the next experiment.

Contribution pitch

Controlled decomposition + honest production null

One paragraph for the call:

We built a controlled OCR instrument to decompose confidence into visual evidence versus language-prior behavior — experiments hard on a production API (blank, unseen script, encoder ablation, position-resolved teacher forcing, text-only n-gram baselines). Max-softmax stayed near ceiling while the correct first grapheme had ~10⁻¹¹ probability on held-out synthetic lines. We then tested transfer to Sarvam Vision: language-level confidence barely moved across a ~40 pp published accuracy spread (Δ0.0027); page-level difficulty ranking did not transfer (ρ≈0.03); offline triage on instrument confidence underperformed random. The lesson is not "confidence is useless" — it is that max-softmax is not necessarily a grounding signal, and next-gen OCR confidence should measure visual contribution explicitly.
