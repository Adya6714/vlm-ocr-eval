Abstract

Diagnosing Indic OCR: exposure, encoding, and confidence

Published Indic OCR scores mix two causes — how often a script was seen in training, and how hard it is to read — and they often count valid alternate Unicode spellings as errors. This project builds apparatus to separate those effects.

What exists: a Stage 0 taxonomy over Tesseract/Surya/PaddleOCR; a HarfBuzz renderer that sets glyph-cluster frequencies (natural / flattened / inverted); a ~19.5M from-scratch instrument model; and probes that ask whether the model is reading or guessing.

Measured: ~20.4% of Tesseract non-exact predictions are Tier 1 encoding variants; glyph-frequency TV ≤ 0.08. Reported (Colab): one early checkpoint stayed ~0.99 confident on blank images with ~0.10 accuracy in its top confidence bucket. Demo LoRA, Sarvam transfer, and cascade are designed but not built — Not built Compute.

Interview walkthrough · 10–15 minutes

What I built, why, and how

This is a diagnostic research codebase for Indic document OCR — not a product and not a leaderboard. Use the sections in order: what it is → why it exists → the question → how the architecture answers it → why these probes → results.

Built: taxonomy · renderer · instrument · probes Probe 1/5 — hindi 9/9 trained; early results reported Bengali — quota-limited, partial Not built: demo VLM · transfer · cascade

What

Four working pieces under src/: error taxonomy, controlled page renderer, from-scratch ~19.5M reader, probe suite that opens its confidence.

Why

Production Indic OCR still shows ~40-point gaps across languages. A low score could mean “rarely seen” or “hard to see” — benchmarks alone cannot tell which. You need a model you own.

How

Measure carefully → set glyph exposure on purpose → train a blank instrument → ask whether it is reading or guessing. Details in the sections below.

SAY THIS

I'd open with this screen. “I didn't ship an OCR product — I built a diagnostic stack so I can tell encoding noise from real misreads, control what the model saw, and check whether confidence means anything.”

Why this exists
1. Motivation

A machine sees pixels, not letters — and Indic OCR is still uneven

A page is a grid of RGB numbers. Modern readers generate text one visual unit at a time from that grid. English clean-print OCR is mostly solved; Indic document OCR is not, for three tangled reasons.

Data skew

Training data is dominated by high-resource languages. A model only gets good at what it has seen enough of.

Script geometry

Devanagari/Bengali conjuncts, matras, and the shirorekha are a harder visual problem than Latin — one “letter” is often several Unicode code points (a grapheme cluster).

Causes tangle

A low language score could be exposure starvation, intrinsic difficulty, or both. A benchmark table cannot untangle that. Untangling requires controlling training exposure and owning the model.

The research question
2. Research question

Three questions a CER number cannot answer

Before architecture: what I actually needed to know.

1. When two strings differ, is that a real misread — or the same reading in different bytes?

Indic orthography allows many valid encodings (anusvara vs nasal, danda vs period, ZWJ/ZWNJ). If you call those “errors,” every engine looks worse than it is, and later “improvements” can be fake.

2. When a language scores low, is it rarely seen, or intrinsically hard to see?

You cannot answer that from a fixed corpus alone. You need to set glyph exposure while holding data volume fixed — natural / flattened / inverted — and train under each condition.

3. When the model is confident, is it reading the image — or guessing from language priors?

A closed API returns text (sometimes a score). It will not give blank-image controls, full next-token distributions, or per-glyph exposure. So some questions are foreclosed unless you own a model you can open.

SAY THIS

This is the slide I'd slow down on. “CER is not enough. I needed encoding-aware scoring, an exposure dial, and an openable model. Everything in the repo exists to answer one of those three.”

How I answered it
3. Method

Four stages — each exists because of one of those questions

Walk this top to bottom. Paths and outputs are concrete; the order is the research order.

0

Measure carefully — error taxonomy

Run Tesseract / Surya / PaddleOCR on real GlotOCR pages. Classify each prediction: exact → Tier 1 encoding → Tier 2 phonetic (ISO 15919) → human residual (genuine misread, dropped matra, order break, hallucination). Align at grapheme clusters, not code points.

src/eval/* → data/predictions/error_taxonomy.csv

Measured: of Tesseract’s 152 non-exact preds (n=180 total), 31 (20.4%) were Tier 1 — not real errors. Large UNREVIEWED remains.

1

Control what the model sees — renderer dial

HarfBuzz shapes Indic text; layouts come from real documents; degradation is a measured distribution. Glyph-cluster frequencies are set to natural / flattened / inverted at matched volume (TV ≤ 0.08). Tier A = dial only; B = degraded; C = real passthrough. Export line crops at 70px for training.

src/renderer/* · export_* → data/manifests/*_*.jsonl

Measured Hindi GT TV: 0.000 / 0.047 / 0.005 · Tier A mean render ~82 ms.

2a

Own an openable model — the instrument

From-scratch ViT encoder + autoregressive decoder (~19.5M), grapheme-cluster vocabulary (not BPE), zero Indic pretraining. fp16 on free Colab T4. generate.py returns text, per-step confidence, and top-k — what probes need. Not meant to beat Tesseract.

src/models/instrument/* → checkpoints (often Colab / Drive)

A separate pretrained “demo” LoRA model is for shipping shape later — deliberately not the same weights as the instrument.

Why these probes
4. Probes

The questions accuracy cannot ask

Each probe exists because a specific failure mode is invisible to CER. Read the “why” column before the numbers on the next section.

ProbeWhy it existsHow it works
1 Exposure Separate “rarely seen” from “hard to see” Train 3 modes × 3 seeds; fit accuracy vs log exposure with glyph fixed effects
2 Confusion Closed APIs hide what the model almost said Aggregate runner-up mass from top-k into a confusion graph
3 Blank/noise Fluent failure can be language-prior guessing Same checkpoint on real / blank / matched noise; compare confidence
4 Equivalence Instrument must use the same notion of “correct” as Stage 0 Re-run Tier 1/2 on instrument outputs
5 Calibration High confidence must mean higher accuracy — especially on starved glyphs Bucket by confidence; check accuracy; cross with Probe 1 exposure
5b Zero-shot True zero exposure (Santhali/Kashmiri never trained) Inference only — not built yet
6 Synth→real Controlled world might lie Compare Tier A/B vs Tier C with the same scorer

Together: if confidence does not track the image, does not track correctness, and starved glyphs behave differently, that is a diagnosis with an implied fix — change the mixture, change decoding, or refuse to trust high confidence on low-exposure scripts.

Results
5. Results

What the numbers say — measured vs reported

Measured = from files in this checkout. Reported = Colab write-up; probe JSONL not in-tree yet.

Measured · Stage 0

Encoding noise is real

Tesseract n=180: 28 exact (15.6%). Of 152 non-exact, 31 (20.4%) Tier 1; 13 genuine-labeled; 108 UNREVIEWED. Surya n=222: ~47% exact; ~16.9% of non-exact are Tier 1.

Measured · Stage 1 / 2a

Dial works; model is small

Hindi GT TV: 0.000 / 0.047 / 0.005. Tier A ~82 ms. Instrument ~19.5M params. Line-crop manifests at 100 pages/mode exist.

Reported · Probes 3 / 5

Early confidence signal

One hindi/natural/seed0 checkpoint, ~5000 steps, n=30. Consistent with undertraining; more steps needed to separate “hasn’t learned the image yet” from “never will.”

Probe 3 — reported

Mean confidence 0.9929 real · 0.9898 blank · 0.9877 noise. Barely any gap.

Probe 5 — reported

All 30 samples in the 0.90–1.00 confidence bucket; accuracy there 0.10.

Spine: (1) stop calling alternate encodings errors; (2) treat glyph exposure as something you set; (3) treat fluent high-confidence failure as calibration/routing, not only CER.

SAY THIS

I'd say measured vs reported out loud. “20% Tier 1 is in-repo. The blank-page confidence is an early Colab signal I'm honest about — and it's exactly the failure mode the probes are for.”

Limits
9. Limitations

Bound by a free Colab T4

fp16 (no bf16), small instrument, early probe sample sizes. More compute changes how much weight the numbers can carry — not the design.

  • Longer training — separates undertraining from structural ungrounded confidence.
  • Larger source corpus — less reuse when rendering 100 pages/mode.
  • Full probe sampling — n=30 was for time; full manifests tighten every number.
  • All four languages — Bengali nine-run; Santhali/Kashmiri need font/render path for 5b.

Designed on purpose — not abandoned

Each item has a reason it waits. Nothing here should be described as shipped. Back to How for what did ship.

StructureStage 3

Reading order + table binding

Kendall tau vs layout complexity; cell↔header binding. Blocked on layout-bank gaps (form / table-embedded).

RLVR

Reward − coverage

Without a coverage penalty, a model raises accuracy by saying less. One planned ablation: remove coverage and quantify silence.

TransferStage 5

Does the finding rhyme at production scale?

~200 Sarvam pages, cached once; pre-specified rank correlation on Tier A and B. Null is still a finding.

CascadeStage 6

Router quality, not cost savings

Sweep escalation thresholds offline against the cache. Instrument is not expected to beat Tesseract on raw accuracy.

Compute ledger
8. Compute ledger

Started, then cut off by Colab quota

This is not the same as Not built Compute. That section is design scope — things deliberately deferred. This section is runs that were started (or ready to start) and stopped by free-tier GPU limits mid-project.

Quota-cut · not a redesign

Bengali full sweep

What ran

Training started for the same 9-run structure as Hindi (3 glyph-frequency conditions × 3 seeds). Hit Colab GPU quota mid-sweep across two separate Google accounts before completing.

What full-scale would show

Same 9-run structure as Hindi. One early Hindi signal worth flagging honestly: the inverted/seed2 run showed 0% accuracy across every sampled confidence bucket (0.3–0.9) despite a non-degenerate confidence spread — unlike natural/seed0’s single-bucket overconfidence. If that generalizes, inverted (rare-glyph-heavy) may need more than 5000 steps to learn anything at all — a distinct failure mode from natural’s confident-but-wrong pattern. That is one seed, not a finding — exactly why the 9-run design exists.

Probe 6 — synthetic-to-real gap

What ran

Code built and import-tested; resize-to-70px for Tier C and held-out-page methodology decided. Not yet run for real numbers.

What full-scale would show

Needs held-out pages 100–109 rendered, plus baselines (Tesseract/Surya/PaddleOCR) against the synthetic line-crop layout — a path the baseline script was never tested against. Genuinely unknown until run, not assumed to work.

Stage 2b prerequisite — base VRAM

What ran

benchmark_base_models.py is written but not executed — the --inspect step to enumerate real LoRA target_modules never completed.

What full-scale would show

One peak-VRAM number per candidate (SmolDocling-256M vs LightOnOCR-1B) under LoRA — the measurement that picks the demo base before any adapter training.

Probe 5b — zero-shot floor

What ran

Not started.

What full-scale would show

Cheapest remaining result: real Santhali/Kashmiri images already sit under data/raw/; inference-only, no training.

None of this changes the design — it changes how much weight the numbers above can carry. That distinction is deliberate, not a hedge.

SAY THIS

I'd separate this from “not built.” Quota cut me off mid-Bengali sweep and before Probe 6 / the VRAM benchmark. The inverted/seed2 zero-accuracy blip is one seed — it's why I planned nine runs, not a claim I'm willing to ship alone.

Stage 0 — Error taxonomy

in progress
src/eval/run_baselines.py

What it doesRuns Tesseract, Surya, and PaddleOCR on every image in the raw data folders and saves each engine's raw text predictions.

Why it existsStage 0's error taxonomy needs ground-truth/prediction pairs per engine; this script produces the prediction half without judging correctness.

verified
src/eval/error_taxonomy.py

What it doesClassifies every engine prediction as an exact match, encoding variant, phonetic variant, a genuine-error label, or still unreviewed — then reports the fractions per engine.

Why it existsThis is Stage 0's deliverable: the interview claim rests on how many apparent OCR errors are really just encoding or phonetic variants.

verified
src/eval/equivalence_tables.py

What it doesA hand-curated lookup of same-sound, different-bytes Unicode pairs so the scorer can mark those diffs as not errors.

Why it existsTier 1 is an uncontroversial encoding fact, kept separate from phonetic judgment calls.

queued
src/eval/transliteration_equivalence.py

What it doesChecks whether two differently spelled strings are the same word by transliterating both to ISO 15919 Latin and comparing.

Why it existsTier 2 is a judgment call about sameness, reported separately from Tier 1 so arguable matches never inflate the encoding-noise number.

done
src/eval/hand_review.py

What it doesInteractive side-by-side viewer that walks ground truth against each engine's prediction and records human labels for unexplained diffs.

Why it existsStage 0 requires reading real engine output by hand before writing the taxonomy, so categories come from observation rather than guessing.

done
src/eval/hand_review_assist.py

What it doesSuggests one of four residual error labels (or an explicit no-fit) for unexplained hand-review cases; the human still confirms or overrides.

Why it existsKeeps suggestion logic testable and out of the interactive prompt loop.

SAY THIS

I'd open with Stage 0 if they ask what I actually measured before building anything. About one in five of Tesseract's apparent Hindi errors were Tier 1 encoding noise — same word, different bytes — not misreads.

The hand-review pass is load-bearing: the taxonomy categories come from sitting with real diffs, not from inventing buckets first.

Stage 1 — Renderer

done
src/renderer/render.py

What it doesTurns text into a page image plus exact per-grapheme ground truth and boxes, using HarfBuzz for Indic shaping.

Why it existsProbe 1 needs controlled glyph exposure and exact boxes from a renderer we own — someone else's corpus gives images but not the dial.

done
src/renderer/glyph_frequency.py

What it doesResamples or synthesizes source text so grapheme-cluster frequencies match natural, flattened, or inverted targets within a fixed tolerance.

Why it existsProbe 1 can only ask whether accuracy tracks exposure if exposure is a dial we set, not a property of whatever corpus we downloaded.

in progress
src/renderer/degradation_profile.py

What it doesMeasures blur, noise, skew, and show-through from real scanned pages and stores them as a sampleable distribution.

Why it existsHardcoding damage numbers would make the degraded condition a fiction; measuring off real scans makes it a distribution we can defend.

in progress
src/renderer/layout_sources.py

What it doesBuilds a reusable bank of real document layouts (Internet Archive, India.gov PDFs, Wikipedia Indic pages) instead of hand-drawn frames.

Why it existsInvented templates would put the project on the wrong side of the clean-synthetic vs. real-scan accuracy gap.

SAY THIS

The renderer isn't a data utility — it's the experimental apparatus. Glyph frequency is a dial I set, verified within TV ≤ 0.08 of target, so Probe 1 can make something closer to a causal claim about exposure.

Layout bank and degradation profile are still partial: extractors exist, but the real-document pools aren't finished, and I say that out loud.

Stage 2a — The instrument

queued
src/models/instrument/tokenizer.py

What it doesBuilds a grapheme-cluster vocabulary from the training corpus — visual units, not BPE subwords.

Why it existsProbe 1 needs exposure per visual unit; BPE merges would tangle how often the encoder saw a glyph with how the tokenizer segmented it.

queued
src/models/instrument/encoder.py

What it doesA small Vision Transformer trained from scratch with no pretrained weights.

Why it existsZero pretraining exposure is what makes Probe 1's exposure manipulation causal instead of a rounding error.

queued
src/models/instrument/decoder.py

What it doesA small autoregressive decoder that emits grapheme-cluster tokens while cross-attending to the encoder's image features.

Why it existsThis is the reading half: given the image and tokens so far, predict what comes next.

queued
src/models/instrument/train.py

What it doesResumable fp16 training loop that wires encoder and decoder on line-crop manifests and checkpoints mid-run.

Why it existsColab sessions die; checkpointing and resume are the normal path, and T4 has no bf16 so training stays in fp16.

queued
src/models/instrument/generate.py

What it doesGreedy decode from a new image, returning text, token ids, per-step confidence, and top-k alternatives.

Why it existsTraining only scores known sequences; every probe that reads a fresh image needs actual generation plus confidence and runner-up mass.

queued
scripts/make_fake_probe1_data.py

What it doesWrites tiny noise line-crop images and manifests so the instrument pipeline can smoke-test without the real renderer.

Why it existsProves training and checkpointing machinery works; it cannot produce a scientific finding.

SAY THIS

I built a ~19M model from scratch with zero Indic pretraining on purpose. A closed API returns text; it does not return runner-up distributions, per-step confidence, or blank-image behaviour.

Everything here is queued on smoke or early runs — real Probe 1 still waits on full line-crop manifests.

What it doesCrops line images out of a rendered page and writes the {image_path, text} JSONL shape train.py expects.

Why it existsThe renderer paints full pages with line boxes; the instrument trains on line crops — this is the adapter between those shapes.

What it doesBatch driver that renders many pages per script and glyph-frequency mode, crops lines, and writes one resumable manifest per mode.

Why it existsProbe 1 and train.py need hundreds of line-crop rows per condition; a killed Colab session must be able to resume.

done
src/data_pipeline/fetch_glotocr.py

What it doesDownloads GlotOCR-bench image/text pairs into data/raw/{language}/ with plain and degraded images plus ground_truth.jsonl.

SAY THIS

train.py wants line crops; render.py paints pages. The export scripts are the boring adapter that unblocks training, and they're written to resume when Colab dies mid-batch.

GlotOCR fetch is how Stage 0 got real ground truth without me hand-transcribing documents.

Probes

queued
src/probes/probe1_exposure.py

What it doesOrchestrates nine instrument training runs — three glyph-frequency conditions times three seeds — skipping any run that already finished.

Why it existsThree seeds per condition are required so an exposure-vs-complexity spread cannot be dismissed as seed noise.

open
src/probes/probe2_confusion_graph.py

What it doesBuilds a confusion graph from runner-up token probabilities across many images — what the model almost said, not just what it said.

Why it existsClosed APIs never return this distribution; owning the model is what makes the confusion structure observable.

open
src/probes/probe3_blank_control.py

What it doesFeeds real, blank, and matched-noise images and compares confidence and text to see whether the model is reading or guessing.

Why it existsIf blank/noise confidence tracks real-image confidence, the number isn't measuring vision — it's language-prior guessing.

open
src/probes/probe5_calibration.py

What it doesBuckets predictions by confidence and checks whether higher confidence actually means higher correctness, using Stage 0 Tier 1/2 equivalence.

Why it existsA well-calibrated model's confidence buckets should track accuracy; divergence is the finding.

open
src/probes/probe6_synthetic_real_gap.py

What it doesCompares each system's accuracy on real documents versus synthetic pages and reports the gap, using the same Tier 1/2 scoring.

Why it existsMetric-only check that synthetic findings still hold on real pages — it aggregates existing predictions, it does not run OCR.

done
src/probes/probe_utils.py

What it doesShared helpers for loading a trained checkpoint and resizing real images to the canonical 70px line height before probing.

Why it existsExtracted so probes do not duplicate load/resize logic; unresized real images would be out-of-distribution by construction.

done
src/probes/generate_instrument_predictions.py

What it doesRuns the instrument on image/text pairs and writes the prediction/ground_truth JSONL shape Probe 6 expects.

Why it existsBridge between trained checkpoints and Probe 6's metric-only aggregator, including resizing real Tier C images first.

SAY THIS

Probe 3 is the soundbite: confidence barely drops on a blank page. Probe 5 says that same checkpoint's top-confidence bucket is only about 10% accurate.

I'd stress these are early, single-condition numbers — hindi/natural/seed0, 30 samples — not a final claim.
